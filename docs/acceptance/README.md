# 验收报告落盘约定

三窗口协作的交接接口:**PM 验收窗口**每次验收完成后,将结论落盘到本目录;
**架构规划窗口**轮询本目录,发现尚无对应规划的新报告即触发下一阶段规划。

## 文件名

`<阶段标识>-<YYYYMMDD>.md`,如 `phase2.2-ranker-20260827.md`。
同一阶段复验(整改后再次验收)追加序号:`phase2.2-ranker-20260827-r2.md`。

## 必备段落

```markdown
# 验收报告:<阶段标识>

- **结论**:✅通过 / ⚠️部分通过 / ❌不通过
- **验收范围**:基线 commit、涉及文件清单、对应 plan 文档
- **规划层核对**:对照 项目规划_修订版.md + plans/*.md 的符合性
- **契约层核对**:降级链 / 检索端点 JSON 形状 / stdlib 策略 是否破坏
- **实证层**:实跑的构建与测试命令及结果(非汇报转述)
- **差距清单**(⚠️/❌ 时必填):每条含文件、现象、整改建议
- **下一阶段建议**(可选):给架构规划窗口的输入
```

## 规则

- 报告是规划窗口的唯一触发源:对话里说过不算,落盘才算。
- ❌ 不通过的报告也会触发规划,但规划内容是整改任务而非新阶段。
- 规划窗口基于某报告起草 plan 后,会在 plan 头部注明"基于验收报告:<文件名>",以此判重。
