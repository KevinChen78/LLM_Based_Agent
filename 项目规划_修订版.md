# LLM-based 团购推荐 Agent —— 项目规划（修订版）

> 本文档在原有分层架构基础上，补充了语言边界、Agent 状态机、工具调用协议、核心接口 schema、数据表 DDL 以及分阶段 MVP 排期，使其从“模块清单”升级为可评审、可落地的工程方案。

---

## 一、任务需求总结

项目目标是开发一款 LLM-based 智能体，向用户推荐团购服务。它不是单纯的对话机器人，而是“理解用户需求 → 追问补全 → 召回候选 → 排序 → 生成解释 → 记录反馈”的完整闭环系统。

### 1.1 核心功能需求

| 需求 | 说明 |
|---|---|
| 自然语言输入 | 例如“今晚三个人吃海鲜，预算 300 左右，上海市区”。 |
| 意图与槽位识别 | 类目、预算、人数、时间、城市、位置、偏好、禁忌等。 |
| 主动追问 | 关键槽位缺失时先追问，不胡乱推荐。 |
| 候选召回 | 从团购商品库中按结构化和语义条件召回候选。 |
| 排序与重排 | 根据用户画像、上下文、业务规则对候选打分排序。 |
| 推荐理由生成 | 输出 Top N 推荐及自然语言解释。 |
| 会话与反馈记录 | 保存对话、推荐日志、用户反馈，用于后续优化。 |
| 合规与兜底 | 敏感内容过滤、事实校验、异常兜底、可观测。 |

### 1.2 非功能需求

- **延迟**：端到端 p99 < 1.5s（含 LLM），LLM 调用 p99 < 3s。
- **可用性**：核心推荐链路可用性 ≥ 99.9%，LLM 失败可降级。
- **可扩展性**：支持水平扩展，Agent 编排层无状态。
- **可解释性**：推荐理由、排序分、召回通道可追踪。
- **合规**：价格/库存/有效期必须来自数据库，禁止 LLM 编造。

## 二、项目架构总结

### 2.1 总体设计原则

1. **控制面与数据面分离**：C++ 负责高并发控制面（API、编排、状态机、工具路由），Python 负责数据面（LLM 聚合、召回索引、排序模型）。
2. **LLM 只做理解、规划、解释**：最终推荐结果由检索、排序、规则系统共同决定。
3. **所有外部依赖必须异步、可观测、可降级**。

### 2.2 技术选型

| 层次 | 选型 | 说明 |
|---|---|---|
| Agent 编排 / API | C++20/23 + coro（自有协程库） | 复用 `coro` 提供的 `Task<T>`、`ThreadPool`、`HTTP Server`；高并发、协程、异步 I/O。 |
| 服务间通信 | gRPC + Protobuf | C++ 与 Python 推荐/模型服务跨语言调用。 |
| LLM 接入 | Python LLM Gateway（vLLM / TGI / 云 API） | C++ 通过 HTTP/gRPC 调用，统一做负载均衡、重试、降级。 |
| HTTP Client | libcurl（同步）+ `coro::ThreadPool` 外包 | Phase 0 先使用；后续可替换为纯协程 Client。 |
| JSON 处理 | nlohmann/json | Header-only，与 C++20 协程配合良好。 |
| 召回索引 | Elasticsearch / OpenSearch + Milvus / pgvector | 结构化过滤 + 向量语义召回。 |
| 排序模型 | Python 服务：LightGBM / XGBoost / 小网络 + ONNX Runtime / Triton | C++ 侧只保留 RankerClient。 |
| 特征存储 | Redis（实时）+ ClickHouse / Hive（离线） | 用户/商品/上下文特征。 |
| 会话记忆 | Redis（短期 TTL 24h）+ PostgreSQL（持久化） |  |
| 用户画像 | PostgreSQL + Redis 缓存 | 离线 Flink/Spark 更新画像标签。 |
| 日志 | spdlog | 高性能同步/异步日志。 |
| 日志 / 追踪 | OpenTelemetry + Prometheus + Grafana + ELK |  |
| 配置 / 密钥 | 环境变量 + 配置中心（Apollo/Nacos）+ Vault | Prompt 版本、模型名、超参可热更新。 |

### 2.4 Agent 状态机

Agent 编排层内部必须维护一个显式状态机，每个 `session_id` 对应一个状态：

```text
        INIT
         │
         ▼
   ┌─────────────┐
   │  SLOT_FILL  │◄─────────────────┐
   │  槽位补全    │                  │
   └──────┬──────┘                  │
          │ 槽位齐全                 │ 用户补充后重新判断
          ▼                          │
   ┌─────────────┐                   │
   │   RETRIEVE  │                   │
   │   候选召回   │                   │
   └──────┬──────┘                   │
          │                          │
          ▼                          │
   ┌─────────────┐                   │
   │    RANK     │                   │
   │   候选排序   │                   │
   └──────┬──────┘                   │
          │                          │
          ▼                          │
   ┌─────────────┐                   │
   │   EXPLAIN   │                   │
   │  推荐理由生成 │                  │
   └──────┬──────┘                  │
          │                          │
          ▼                          │
   ┌─────────────┐                   │
   │   RESPOND   │───────────────────┘
   │   输出回复   │
   └─────────────┘
```

- 状态转换由 `TaskPlanner` 根据 LLM 结构化输出决定。
- 每个状态失败均可进入 `FALLBACK`：返回兜底推荐或固定文案。

## 四、头文件级接口设计总结

### 4.1 公共基础类型（common）

```cpp
namespace agent {

struct UserContext {
    std::string user_id;
    std::string session_id;
    std::string city;
    std::string language = "zh";
    std::string device_type;
    double longitude = 0.0;
    double latitude = 0.0;
};

struct SlotValue {
    std::string slot_name;
    std::string value;
    double confidence = 1.0;
};

struct IntentResult {
    std::string intent;               // recommend / ask_info / chitchat / complain
    std::vector<SlotValue> slots;
    bool needs_clarification = false;
    std::vector<std::string> missing_slots;
};

struct ClarificationQuestion {
    std::string question;
    std::vector<std::string> candidate_options;
};

struct RecommendationItem {
    std::string item_id;
    std::string merchant_id;
    std::string title;
    std::string category;
    double price = 0.0;
    double original_price = 0.0;
    std::string city;
    std::vector<std::string> tags;
    double score = 0.0;               // 排序分
    std::string reason;               // 推荐理由
};

struct RecommendationResult {
    std::string session_id;
    std::string response_text;
    std::vector<RecommendationItem> items;
    std::string trace_id;
};

struct ToolCall {
    std::string tool_name;
    std::string call_id;
    std::string arguments_json;       // 严格按 Tool Schema 序列化
};

struct ToolResult {
    std::string call_id;
    bool success = false;
    std::string result_json;
    std::string error_message;
};

struct Status {
    int code = 0;
    std::string message;
    bool ok() const { return code == 0; }
};

} // namespace agent
```

### 4.2 Agent 编排层接口

```cpp
namespace agent {

// Agent 单条请求入口
class AgentOrchestrator {
public:
    virtual ~AgentOrchestrator() = default;

    struct Request {
        UserContext user_context;
        std::string user_message;
    };

    // 协程返回
    virtual Task<RecommendationResult> Handle(Request req) = 0;
};

// 任务规划器：解析意图、判断状态、生成下一步计划
class TaskPlanner {
public:
    struct Plan {
        std::string next_state;       // SLOT_FILL / RETRIEVE / RANK / EXPLAIN / RESPOND
        std::vector<SlotValue> filled_slots;
        std::vector<std::string> missing_slots;
        std::vector<ToolCall> tool_calls;
        std::optional<ClarificationQuestion> clarification;
    };

    virtual Task<Plan> PlanNextStep(
        const UserContext& ctx,
        const std::vector<ConversationTurn>& history,
        const std::string& user_message) = 0;
};

// 工具注册表：运行时注册所有可用工具及其 JSON Schema
class ToolRegistry {
public:
    void Register(std::shared_ptr<ITool> tool);
    std::shared_ptr<ITool> Get(const std::string& name) const;
    std::vector<std::string> ListNames() const;
};

// 工具基类
class ITool {
public:
    virtual ~ITool() = default;
    virtual std::string Name() const = 0;
    virtual std::string SchemaJson() const = 0;   // JSON Schema
    virtual Task<ToolResult> Execute(const ToolCall& call) = 0;
};

} // namespace agent
```

### 4.3 LLM 层接口

```cpp
namespace agent {

enum class LlmModelTier {
    PRIMARY,      // 主力模型，质量高、成本高
    FALLBACK,     // 降级模型，成本低、速度快
    FAST          // 轻量模型，用于简单任务
};

class LlmClient {
public:
    struct Options {
        LlmModelTier tier = LlmModelTier::PRIMARY;
        int max_tokens = 1024;
        double temperature = 0.3;
        std::chrono::milliseconds timeout{3000};
        int max_retries = 1;
    };

    virtual Task<LlmResponse> Chat(
        const std::vector<LlmMessage>& messages,
        const Options& options) = 0;

    virtual bool Healthy() const = 0;
};

class LlmResponseParser {
public:
    // 要求 LLM 必须输出 JSON，解析为结构化对象
    virtual Status ParseIntent(const std::string& raw, IntentResult* out) = 0;
    virtual Status ParsePlan(const std::string& raw, TaskPlanner::Plan* out) = 0;
    virtual Status ParseExplanation(const std::string& raw, std::string* out) = 0;
};

} // namespace agent
```

## 五、数据表设计总结

采用 **PostgreSQL 为主存储**，配合 **pgvector 插件** 存储商品向量，Redis 存储会话热数据，Elasticsearch/Milvus 负责检索。

### 5.1 核心表 DDL

```sql
-- 用户基础信息
CREATE TABLE users (
    user_id        BIGSERIAL PRIMARY KEY,
    phone_hash     VARCHAR(64) UNIQUE NOT NULL,
    register_city  VARCHAR(32),
    created_at     TIMESTAMPTZ DEFAULT NOW(),
    updated_at     TIMESTAMPTZ DEFAULT NOW()
);

-- 用户画像（宽表，离线更新为主）
CREATE TABLE user_profiles (
    user_id            BIGINT PRIMARY KEY REFERENCES users(user_id),
    preferred_cities   VARCHAR(32)[] DEFAULT '{}',
    preferred_categories VARCHAR(64)[] DEFAULT '{}',
    price_sensitivity  INT DEFAULT 5,        -- 1~10
    dietary_tags       VARCHAR(64)[] DEFAULT '{}',  -- 素食、清真、海鲜过敏等
    avg_budget         DECIMAL(10,2),
    embedding          VECTOR(768),          -- 用户兴趣向量
    updated_at         TIMESTAMPTZ DEFAULT NOW()
);

-- 会话表
CREATE TABLE sessions (
    session_id     VARCHAR(64) PRIMARY KEY,
    user_id        BIGINT NOT NULL REFERENCES users(user_id),
    city           VARCHAR(32),
    current_state  VARCHAR(32) DEFAULT 'SLOT_FILL', -- 状态机状态
    context_json   JSONB DEFAULT '{}',       -- 当前槽位、中间结果
    created_at     TIMESTAMPTZ DEFAULT NOW(),
    updated_at     TIMESTAMPTZ DEFAULT NOW(),
    expires_at     TIMESTAMPTZ DEFAULT NOW() + INTERVAL '72 hours'
);
CREATE INDEX idx_sessions_user_id ON sessions(user_id);
CREATE INDEX idx_sessions_expires ON sessions(expires_at);

-- 对话消息表
CREATE TABLE conversation_messages (
    message_id     BIGSERIAL PRIMARY KEY,
    session_id     VARCHAR(64) NOT NULL REFERENCES sessions(session_id),
    turn_id        INT NOT NULL,
    role           VARCHAR(16) NOT NULL CHECK (role IN ('user','assistant','tool')),
    content        TEXT NOT NULL,
    intent_json    JSONB,                    -- 意图与槽位
    tool_calls_json JSONB,                   -- 工具调用记录
    latency_ms     INT,                      -- 本 turn 耗时
    created_at     TIMESTAMPTZ DEFAULT NOW()
) PARTITION BY RANGE (created_at);
CREATE INDEX idx_messages_session ON conversation_messages(session_id, turn_id);

-- 团购商品主表
CREATE TABLE groupbuy_items (
    item_id        VARCHAR(64) PRIMARY KEY,
    merchant_id    VARCHAR(64) NOT NULL,
    title          VARCHAR(256) NOT NULL,
    category       VARCHAR(64) NOT NULL,
    city           VARCHAR(32) NOT NULL,
    district       VARCHAR(64),
    price          DECIMAL(10,2) NOT NULL,
    original_price DECIMAL(10,2),
    sold_count     INT DEFAULT 0,
    rating         DECIMAL(2,1) DEFAULT 5.0,
    valid_start    DATE,
    valid_end      DATE,
    status         SMALLINT DEFAULT 1,      -- 0 下架 1 上架
    attributes     JSONB DEFAULT '{}',       -- 标签、套餐内容等
    embedding      VECTOR(768),              -- 语义向量
    updated_at     TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_items_city_category_price ON groupbuy_items(city, category, price);
CREATE INDEX idx_items_valid_end ON groupbuy_items(valid_end);

-- 商家表
CREATE TABLE merchants (
    merchant_id    VARCHAR(64) PRIMARY KEY,
    name           VARCHAR(256) NOT NULL,
    city           VARCHAR(32) NOT NULL,
    address        VARCHAR(512),
    phone          VARCHAR(32),
    business_hours JSONB,
    latitude       DECIMAL(10, 7),
    longitude      DECIMAL(10, 7),
    status         SMALLINT DEFAULT 1
);

-- 商品排序特征（实时/离线融合后写入）
CREATE TABLE item_features (
    item_id        VARCHAR(64) PRIMARY KEY REFERENCES groupbuy_items(item_id),
    ctr_7d         DECIMAL(8,6) DEFAULT 0,
    cvr_7d         DECIMAL(8,6) DEFAULT 0,
    click_count_7d INT DEFAULT 0,
    order_count_7d INT DEFAULT 0,
    category_hot_score DECIMAL(8,4) DEFAULT 0,
    features_json  JSONB DEFAULT '{}',
    updated_at     TIMESTAMPTZ DEFAULT NOW()
);

-- 推荐日志（大表，按日期分区）
CREATE TABLE recommendation_logs (
    log_id         BIGSERIAL,
    trace_id       VARCHAR(64) NOT NULL,
    session_id     VARCHAR(64) NOT NULL,
    user_id        BIGINT NOT NULL,
    request_text   TEXT,
    slots_json     JSONB,
    recall_channels JSONB,                   -- 各通道召回数
    ranked_items   JSONB,                    -- Top N 结果及分数
    response_text  TEXT,
    latency_ms     INT,
    model_version  VARCHAR(32),
    created_at     TIMESTAMPTZ DEFAULT NOW()
) PARTITION BY RANGE (created_at);
CREATE INDEX idx_rec_logs_trace ON recommendation_logs(trace_id);
CREATE INDEX idx_rec_logs_session ON recommendation_logs(session_id, created_at);

-- 反馈日志
CREATE TABLE feedback_logs (
    feedback_id    BIGSERIAL PRIMARY KEY,
    trace_id       VARCHAR(64) NOT NULL,
    session_id     VARCHAR(64) NOT NULL,
    user_id        BIGINT NOT NULL,
    item_id        VARCHAR(64),
    feedback_type  VARCHAR(32) NOT NULL CHECK (feedback_type IN ('impression','click','order','like','dislike','explicit')),
    reward         SMALLINT,                 -- 显式反馈：-1 / 0 / 1
    comment        TEXT,
    created_at     TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_feedback_trace ON feedback_logs(trace_id);
CREATE INDEX idx_feedback_user ON feedback_logs(user_id, created_at);

-- LLM 调用审计
CREATE TABLE llm_calls (
    call_id        BIGSERIAL PRIMARY KEY,
    trace_id       VARCHAR(64) NOT NULL,
    session_id     VARCHAR(64) NOT NULL,
    model          VARCHAR(64) NOT NULL,
    prompt_tokens  INT,
    completion_tokens INT,
    latency_ms     INT,
    raw_request    JSONB,
    raw_response   JSONB,
    status         VARCHAR(16),              -- success / parse_error / timeout
    created_at     TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_llm_trace ON llm_calls(trace_id);
```

### 5.2 分区建议

- `conversation_messages`、`recommendation_logs` 按 `created_at` 月分区。
- `groupbuy_items` 数据量可控（百万级），先按 `city` + `category` 分索引即可，无需分区。

```text

  ▼

  ▼

           │
           ├──► RankerClient ──► 排序服务（Feature Store + 模型）

           │
           └──► ExternalToolClient ──► 地图/营业/券信息
           │
           ▼
      PolicyEngine（输入/输出 Guard、业务规则）
           │
           ▼
      ResponseComposer
           │
           ▼
      返回 ChatResponse
           │
           ▼
      异步写入：recommendation_logs / conversation_messages / llm_calls
```

### 6.1 关键控制点

| 控制点 | 说明 |
|---|---|
| 追问策略 | 缺失 `city`、`budget`、`people` 任一即进入 `SLOT_FILL`。 |
| 召回过滤 | 城市、价格区间、有效期、状态为硬性过滤，不经过 LLM。 |
| 排序校验 | 排序结果必须包含真实 item_id，C++ 侧校验数据库存在性。 |
| 推荐理由 | 由 LLM 根据排序结果生成，但价格/库存必须从商品表回填。 |
| 失败降级 | LLM 超时/解析失败 → 返回热门榜 + 固定解释；检索失败 → 返回兜底列表。 |

## 七、MVP 范围总结与排期

### 7.1 分阶段 MVP

原有 MVP 范围过大，建议拆为三阶段，每阶段都有可演示产出。

| 阶段 | 周期 | 目标 | 核心交付 | 成功标准 |
|---|---|---|---|---|
| **Phase 0：Agent 闭环** | 4 周 | 验证 LLM 理解、状态机、工具调用、会话 | API Server + AgentOrchestrator + TaskPlanner + LlmClient + SessionMemoryStore；召回/排序用 Mock 数据（50–100 条商品） | 用户输入自然语言 → 系统能正确追问/推荐/解释/记录会话 |
| **Phase 1：真实召回** | 4 周 | 接入真实检索能力 | Elasticsearch + pgvector 索引；多路召回；FilterChain；商品/商家数据导入 | 召回结果覆盖城市/价格/类目/语义约束 |
| **Phase 2：学习式排序** | 4–6 周 | 接入排序模型与反馈闭环 | Feature Store（Redis）；排序模型服务（Python gRPC）；A/B 实验；反馈日志回流 | 排序指标（点击率、转化率）优于规则基线 10%+ |

### 7.2 Phase 0 详细任务拆分

| 周次 | 任务 | 负责人建议 |
|---|---|---|
| W1 | 工程脚手架：C++ 项目结构、CMake、Protobuf、gRPC、coro HTTP Server 接入 | 后端基建 |
| W1 | LLM Gateway（Python）：封装 OpenAI/Claude/本地模型，统一接口 | 算法/模型 |
| W2 | Agent 状态机、TaskPlanner、PromptBuilder、JSON 输出 Schema | 后端核心 |
| W2 | SessionMemoryStore（Redis + PG）、对话历史读写 | 后端核心 |
| W3 | Mock Retriever / Ranker、ToolRegistry、ResponseComposer | 后端核心 |
| W3 | API Server、鉴权、限流、Trace、错误处理 | 后端基建 |
| W4 | 集成测试、示例对话、Prompt 调优、文档与演示 | 全组 |

### 7.3 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| LLM 输出不稳定 | 状态机跳变、推荐错误 | 强制 JSON Schema、解析失败重试、人工兜底 Prompt。 |
| C++ 生态对 LLM/ML 支持弱 | 开发效率低 | 控制面用 C++，LLM/排序/召回用 Python/Go 服务。 |
| 推荐链路延迟高 | 用户体验差 | 异步 I/O、检索/排序 200ms 超时、LLM 3s 超时、缓存热点结果。 |
| 数据幻觉导致价格错误 | 交易纠纷 | 输出 Guard 强制回填数据库字段，禁止 LLM 输出未校验的价格。 |

## 九、评审结论

修订后的方案相比原方案，补全了以下关键内容：

1. **明确 C++ / Python 语言边界**，避免在 C++ 中硬写推荐模型。
2. **引入显式 Agent 状态机**，让追问、召回、排序、解释、回复有清晰流转。
3. **定义 LLM 结构化输出与工具 Schema**，提高系统可控性和可测试性。
4. **补充具体存储选型与 DDL**，从表名清单升级到可执行的建表脚本。
5. **拆分三阶段 MVP**，降低一次性交付风险，每阶段都有可验证目标。
6. **补充 SLO、风控、兜底、可观测细节**，使方案具备生产意识。

建议下一步：
- 用 1 天时间召开技术评审会，确认 C++ 框架选型（已确定复用 `coro` 协程库）和 LLM 供应商/模型。
- Phase 0 先写出可运行的 Agent 闭环 Demo，再决定是否继续投入 Phase 1/2。
